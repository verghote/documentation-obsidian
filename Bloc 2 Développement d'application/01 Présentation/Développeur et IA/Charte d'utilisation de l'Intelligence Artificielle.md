# Préambule

Les outils d'Intelligence Artificielle (ChatGPT, Copilot, Gemini, Claude, etc.) font désormais partie de l'environnement professionnel des développeurs et des techniciens informatiques. Leur utilisation est autorisée dans le cadre de la formation BTS SIO, à condition qu'elle reste un **outil d'apprentissage et d'assistance** et non un moyen de contourner les objectifs pédagogiques.

L'objectif de cette charte est de définir les bonnes pratiques attendues lors de l'utilisation de l'IA dans les projets, travaux pratiques et activités de développement.

# 1. L'IA est un assistant, pas un remplaçant

L'IA doit être utilisée pour :

- comprendre un concept ;
- obtenir des explications sur un algorithme ;
- découvrir des pistes de résolution ;
- **améliorer un code déjà écrit** ;
- réécrire un code pour respecter une mise en forme définie ;
- proposer des améliorations ergonomiques ou graphiques ;
- identifier des erreurs ou des points d'amélioration.

L'IA ne doit pas être utilisée pour :

- réaliser intégralement un projet à votre place ;
- produire du code que vous ne comprenez pas ;
- contourner les consignes ou les objectifs pédagogiques ;
- remplacer le travail de conception et de réflexion.

L'IA doit être constamment surveillée car :
+ elle a des hallucinations (elle invente)
+ elle ne propose jamais au départ la meilleure solution, voir même des solutions incohérentes dans le contexte métier
+ elle ne comprend pas les subtilités du contexte métier et ne dispose pas toujours de la totalité de ce contexte faute de lui avoir donner
+ Elle est programmée pour être souvent d'accord avec vous

# 2. Réfléchir avant de consulter l'IA

La démarche attendue est la suivante :

1. Comprendre le problème.
2. Analyser les besoins.
3. Concevoir une solution.
4. Produire un premier code ou une première proposition.
5. Tester et corriger.
6. Consulter éventuellement l'IA pour obtenir un avis ou des améliorations.

L'IA intervient donc **après une première réflexion personnelle** et non comme point de départ systématique.
Elle est souvent utile pour améliorer le code HTML et CSS d'une interface afin de la rendre web responsive et souvent bien plus jolie.

# 3. Comprendre tout code utilisé

Tout étudiant doit être capable de :

- expliquer le fonctionnement du code présent dans son projet ;
- justifier les choix techniques réalisés ;
- modifier le code fourni ;
- corriger une erreur dans ce code ;
- répondre aux questions de l'enseignant concernant son fonctionnement.

Un code proposé par une IA ne doit jamais être intégré dans un projet sans avoir été :

- lu ;
- compris ;
- testé ;
- adapté au contexte du projet.

**==Si vous ne pouvez pas expliquer une portion de code, vous ne devez pas l'utiliser.==**

# 4. Savoir remettre en question les propositions de l'IA

L'IA peut :

- produire du code erroné ;
- proposer des solutions inefficaces ;
- ignorer certaines contraintes du projet ;
- inventer des informations techniques ;
- utiliser des technologies non demandées.

Une proposition de l'IA n'est jamais considérée comme correcte par défaut.

L'étudiant doit développer un esprit critique et être capable de :

- vérifier les réponses obtenues ;
- comparer plusieurs solutions ;
- identifier les erreurs ;
- refuser une proposition lorsqu'elle n'est pas adaptée.

# 5. Respect des spécifications techniques

Les projets réalisés dans le cadre du BTS SIO doivent respecter les consignes données.

Par conséquent :

- les classes techniques fournies ainsi que les composants client doivent être utilisées sans subir la moindre modification (sauf accord);
- les bibliothèques imposées doivent être conservées ;
- l'architecture demandée doit être respectée ;
- les contraintes techniques définies dans le sujet doivent être appliquées.

L'IA ne doit jamais être utilisée pour contourner ou remplacer les éléments techniques imposés par l'enseignant.

**Exemple :**

Si un projet fournit une classe d'accès aux données ou une bibliothèque spécifique, l'étudiant doit l'utiliser même si l'IA propose une autre solution.

# 6. Priorité au code personnel

La méthode recommandée est :

1. Écrire soi-même la solution.
2. La tester.
3. Identifier ses limites.
4. Demander éventuellement à l'IA :
    - une optimisation ;
    - une simplification ;
    - une amélioration de lisibilité ;
    - une amélioration de l'interface utilisateur ;
    - une vérification de bonnes pratiques.

L'objectif est de rester l'auteur principal du projet.

# 7. Utilisation recommandée de l'IA

L'IA est particulièrement pertinente pour :

- expliquer un message d'erreur ;
- proposer des cas de test ;
- documenter un programme ;
- générer des commentaires ;
- améliorer l'ergonomie d'une interface (HTML et CSS) ;
- suggérer des améliorations de performance ;
- vérifier la qualité du code ;
- découvrir de nouvelles approches techniques, de nouvelles instructions.

L'IA est un excellent outil, mais en dépendre excessivement peut freiner votre créativité, diminuer votre intérêt pour la programmation, limiter votre compréhension globale et vous faire perdre du temps sur le long terme.
# 8. Évaluation

Lors des évaluations, projets et soutenances :

- l'étudiant reste responsable de l'intégralité du code présenté ;
- il doit pouvoir expliquer ses choix ;
- il doit être capable de modifier son code en direct et peut éventuellement recourir à l'IA pour le générer plus rapidement que lui ;
- il doit démontrer sa compréhension des solutions mises en œuvre.

Une utilisation excessive de code non compris pourra être considérée comme contraire aux objectifs de la formation.

# 9. Principe fondamental

> L'IA est un outil d'apprentissage pour les développeurs junior et une outil d'amélioration pour tout développeur.
> Elle doit aider à devenir un meilleur développeur, pas à éviter d'apprendre à développer.
> L'IA devient principalement un assistant pour un développeur confirmé, Il est utilisé car il est plus rapide, mais ses propositions restent des propositions que le développeur doit analyser, discuter, et valider

**Le développement de compétences techniques, de capacités d'analyse, de réflexion et d'autonomie reste la priorité de la formation BTS SIO.**

**Les outils changent. Les modèles changent. Les interfaces changent. Mais les fondamentaux restent utiles.**
